# Bounded upstream reduction title

This experimental title retains the exact upstream `block_reduce` compiler object. A declaration-only HIP companion calls its original compiler stub. The compiler authority confirms exactly one module constructor/destructor, no companion device bundle, and byte-identical original device and wrapper sections for both host targets.

Three cases preserve 16 groups, 1024 threads per group and 4096 dynamic LDS bytes: original-shape ones, mixed wave masks, and bounded signed inputs with a logical 16377-element tail. The independent parent fixture supplies 48 recorded results. Every case checks complete guarded input/mask/output arrays: 48 outputs, 72 guard elements, nine allocations/frees. High mask bits are deliberately varied and ignored by wave32 selection. The companion calls finish exactly once; the title checks readiness and final compiler unregister.

The original compiler object still defines its sample main. The native CRT is therefore redirected to the distinct C symbol `ps5hip_reduction_title_main`, and the linked startup audit requires that symbol to call `ps5hip_reduction_companion_main`. Original main and object bytes are retained. The title uses the existing elevation helper, configured results directory, exclusive log creation and finite shell-exit lifecycle.

Offline model transport checks the entire materialized code image and exact entry address, then computes a direct selected-index CPU sum. It does not execute GPU ISA. Runtime model includes no-op/stale/corrupt output, mask-width and tail errors, input/mask/output guard corruption, and code-image/entry/submit failures. Unknown GPU ownership retains all seven live allocations. Native link/provider/startup, FSELF and package audits and eventual console execution remain distinct qualification steps. Exception/vector use follows existing native clients and must pass the actual PS5 link and runtime unwind probe; offline models alone do not establish it.
