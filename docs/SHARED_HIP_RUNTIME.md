# Shared serialized HIP runtime

`src/hip_runtime.cpp` owns the measured compiler registration ABI, scalar argument snapshots, direct-memory registry, lazy backend/queue and blocking launch lifecycle. A statically linked client contract chooses only explicit Initial, LDS, BufferScratch or Geometry preparation. This is not a general HIP runtime, capability query, stream scheduler or support for arbitrary host pointers. Private-call entry and combined resource profiles remain rejected.

`tools/hip_vector_control.cpp` is the original vector contract and helper-name adapter. Existing 73-element, two-launch logs, 26 host failure modes and 22 title lifecycle cases remain controls. The new four-kernel client is independently compiled from genuine HIP syntax; its adapter limits symbols, exact metadata, shapes, scalar values and live allocation extents before native allocation or AGC initialization. Compilation, synthetic backend models and a PS5 link are separate from GPU execution.

Capture validates every argument's kind, width, offset, bounds and overlap before reading the argument-address array. Global pointers are 64-bit; supported values are 32- or 64-bit. Each copy also checks the destination snapshot width. Compiler-generated address/value storage is a trusted readable, immutable input for the synchronous call; this API cannot discover arbitrary host mappings. Captured values own their bits, while launch preparation resolves actual registered device-allocation remainders and retains their owners.

The fixed diagnostic mode requires its expected functions before launch. The additive [bounded reusable policy](BOUNDED_HIP_RUNTIME.md) accepts a variable nonzero function inventory and zero or more launches without experiment names, answers or completion counts. Its single-module limit remains explicit; any failed module or function registration latches partial state and retires existing bindings when safe. Reading the last error cannot repair that latch or terminal memory/submission failure. Duplicate unregister cannot succeed. Constructor registration performs no native allocation or AGC initialization. Backend initialization is attempted once, lazily after complete preparation; initialization failures explicitly close temporary allocations.

The shared state owns the queue until process teardown. An uncertain submission retains GPU leases, poisons the registry and rejects copying, freeing, relaunch and successful unregister. Known-complete or pre-submit cleanup failures are terminal but are not described as unresolved GPU work. Explicit launch temporaries include code, kernargs and optional scratch. No cleanup relies on resource-vector positions.

The genuine compiler destructor unregisters before state destruction. A first-declared sentinel records destruction after every other member; final callbacks read only trivial process-lifetime observations. Final proof requires genuine unregister, no partial/terminal latch, no remaining data, no pending call configurations and a healthy queue (or no attempted backend initialization for reusable zero-work operation). Expected completion counts remain an additional fixed-diagnostic condition. Ownership finalization is separate from the application's numerical result; a normal main return alone is insufficient.

Host models execute real runtime/allocator/queue code with syscall/backend doubles, not shader ISA emulation. Fixed mapped shader-address windows are not heap-redzone allocations; explicit guards check their extents. The recorded ASan `protect_shadow_gap=0` accommodation does not prove native allocator safety. These merged sources require their own qualification and carry no inherited hardware pass.
