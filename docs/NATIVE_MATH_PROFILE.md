# Offline native FP32 math profile

`fp32_math` connects the existing four LLVM 18.1.8 OCML compiler fixtures to
the native canary lifecycle. It has not executed on a GPU. It does not qualify
OCML generally, full OCKL, HIP runtime behavior, or numerical throughput.

The builder selects only the frozen O2 object for the requested gfx1013 or
gfx1030 target. `tools/math_native_inputs.json` pins the original compiler
receipt, its exact report and four code objects, and the numerical oracle
sources. `tools/math_native_fixture.py` rechecks the compiler sources, artifact
inventory, copied device-library sources and HIP headers, library bitcode,
constant policy, tool identities and existing ISA/metadata/caller/driver audits.
No device object or shared compiler library is regenerated by the native build.
The build, staging and local case verifier bind the same profile, code bytes and
oracle sources. A changed oracle requires deliberate regeneration and review.

The launch has 257 input float bit patterns, six results per input (1542 words),
five groups of 64 threads and 63 inactive invocations. The output allocation
requests room for all 320 invocations (1920 words). Both allocations have leading
guards, and validation checks every rounded backing word outside the logical
input/output extents, including all 378 inactive result words. Every input must
remain bit-identical. Each active output starts with a per-index poison that the
numeric oracle rejects, including for expected quiet-NaN results. Completion
without shader writes cannot pass.

The independent generated oracle defines exact FMA and sqrt results and declared
finite error envelopes for sin, exp, log and tanh. Special values, zero signs and
subnormal behavior follow its explicit contract. The native checker performs
integer classification and comparisons, without calling host libm. The log says
`numeric_values`, not `exact_values`, and includes the full contract digest.
See `tools/math_oracle_contract.json` and the generator's provenance for the
precise input corpus and engineering limits; these are not hardware observations.
Finite envelopes are 4/3/3/5 exact-reference ULP for sin/exp/log/tanh respectively.
Sign preservation, exact zero and infinity classes, and saturated tanh endpoints
are additional engineering requirements, stronger than an unrestricted generic
ULP envelope. Passing this finite corpus would not establish all-domain accuracy.

The real object needs 280 kernarg bytes: two pointers, a four-byte count, padding
to offset 24, and the full 256-byte COv5 implicit area. The existing checked
initial-launch API generates all 13 supported hidden geometry fields and zeros
every other implicit byte. Six user SGPR slots are emitted, with the kernarg
pointer in slots 4/5. There is no scratch or LDS allocation. Four actual-object
host tests independently compare all 280 bytes, entry/resources, SGPR slots and
dispatch geometry and exercise malformed arguments and layouts.

The native queue, 2000-ms GPU completion deadline, exception/quarantine behavior,
resource retention, allocation closure and finite shell-exit lifecycle are reused.
The host oracle test never invokes a GPU API. It checks all active-output poison
mutations, every input mutation and complete rounded guards. Shared queue tests
cover uncertain completion and retained resources separately. Compile-only SDK
checks are not evidence of a successful native link or hardware execution.

This candidate derives from `a27ec69`, including checked hidden argument parsing
and packing that postdate the successful G2 arithmetic source. Its loader and
launch objects therefore differ from the G2 candidate; it must not be described
as a harness-only change. Before a hardware experiment, freeze and review the
combined source, build in a private native-tools export, verify imports/startup/
FSELF and full package extraction, and apply the current environment-specific
idle, provenance and lifecycle criteria. No deployment is performed here.

After source freeze, the offline builder invocation is:

```sh
python3 tools/build_native_canary.py --native-source /path/to/pinned/native/source \
  --target gfx1013 --kernel fp32_math --ocml-probes /path/to/frozen/ocml-math-v2 \
  --shell-exit-probe
```

`PS5HIP_OCML_FIXTURE_DIR` enables all four actual-object packing tests. The regular
CTest suite also runs the fixed numeric oracle, native guard model and build/
stage/verifier/log mutation tests. Pass `--fixtures` to
`tests/math_native_profile_test.py` for full frozen compiler-input rehashing.
